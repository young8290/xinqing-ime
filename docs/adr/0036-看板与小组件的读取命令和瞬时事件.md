# 0036 看板与小组件的读取命令和瞬时事件
- 状态：提议
- 日期：2026-10-10；提议人：D；待 B（状态与计时口径、`mood:typo` / `typing:pulse`）、C（`comfort_log`、设置键注册表）、E（隐私、文案与验收）评审

## 背景
看板（07 FR-DSH-02～04）、小组件底栏与一句话区（FR-WGT-04/05）、小精灵“晃一下”（DS-MOTION-02）和全局快捷键（FR-ENT-04）
都缺后端入口：库里已经有 `mood_state`、`daily_summary`、`comfort_log`、`diary` 等数据，总线上也有 `HubEvent::Typo`，
但没有给前端读的命令和事件。D 的交接文档把这些列为“等 B / C 先给统计或列表命令”；B、C 的后端都已完成，
D 作为 `bindings.ts` 契约负责人（13 第 3.1 节）按现有数据补一组只读命令，不新增迁移。

## 决策
1. **只读命令四个**（`src-tauri/src/commands/dashboard.rs`，统计是 `core/src/domain/dashboard.rs` 的纯函数）：
   - `comfort_list(date)`：某天的暖心话 `{id, ts, text, ai_generated, trigger, feedback}`，从早到晚。小组件重开时取最后一条做“今日一句”，
     看板“今日一句”列表带反馈状态；
   - `day_stats(date)`：`{typing_min, rests_due, rests_done, water, comforts, dominant, timeline}`。时间线把相邻、同状态、
     间隔不超过 5 分钟的状态记录合并成一段，每段带最后一条记录的 `mood_id`，点开用 `state_explain(mood_id)`；
   - `month_moods(YYYY-MM)`：每天的主导天气与有没有日记；
   - `week_stats(date)`：那周（周一起）的每日计数、状态分布、7 × 24“低落 / 疲劳”热力图、休息完成率、饮水、新增日程、完成待办、
     专注分钟与一句话总结。周统计复用周信的 `read_week` 与 `letter::stats`，与周信同一口径。
2. **主导天气**按 FR-DSH-03 字面：窗口数最多的状态，不计 `unknown`；有效窗口 < 10 个的天为空。与晚间小结的
   `evening::dominant` 不同，这里**不**要求占比 ≥ 40%，日历每天都要有一个图标。并列时按 流畅 > 犹豫 > 低落 > 烦躁 > 疲惫 取。
3. **周报一句话**用已有的 `weekly_line.toml`（此前没有加载代码），按文件头注释的规则依次判断：“低落 / 疲劳”最多（≥ 2 次）的钟点在
   22 点以后（含凌晨 0–4 点）→ `late_tired`；完成率 ≥ 70% → `rest_high`；< 30% → `rest_low`；流畅占比 ≥ 60% → `sunny`；否则 `plain`。
   `{hour}` 用 12 小时说法（22 → 10、23 → 11，零点以后统一说 12），`{slot}` 用周信的最累时段，`{rate}` 写成“85%”；
   变量缺值的句子跳过。同一周用同一句（种子 = 周一的日序）。加载走 `load_with_fallback`，用户目录同名文件可整体覆盖，
   校验失败退回出厂文件；全部失败时用兜底句。
4. **`comfort:new` 加字段 `trigger`**（`auto` / `self_report`），取自暖心话服务已有的 `ComfortTrigger`。界面据此把负面自评后的回应
   放进卡片层并给出“和晴晴聊聊”（FR-STA-10 第 2 条），不再靠“刚自评过”去猜。只加字段，旧前端忽略它不受影响。
5. **两个瞬时事件**（`src-tauri/src/pulse.rs` 订阅总线）：
   - `mood:typo`：转发 `HubEvent::Typo`，两次至少隔 1.5 秒，“晃一下”0.5 秒的动画不会连成闪烁（DS-MOTION-04）；
   - `typing:pulse { keys: [{ts, iki_ms, backspace}] }`：打字心电图。只取 XQP `key` 的键间间隔（上限 5 秒）和是不是退格，
     **不含键值、不含文字、不落库**；来源口径同状态识别（声明 `tsf_trace` 时只看 tsf），方向键等不算；
     每 100 毫秒批量推一次（≤ 10 Hz），**只在看板窗口看得见时推**，否则丢弃。
6. **全局快捷键**（FR-ENT-04 的 Hub 部分）：新增设置键 `hotkey.chat` / `hotkey.widget` / `hotkey.dashboard`，默认 `ctrl+alt+q` / `w` / `d`，
   新格式 `SettingItem::Hotkey`：至少一个 Ctrl / Alt / Win 加一个字母、数字或 F1–F24，空串表示不设。出厂值放标量字段，
   清空即真正关闭（AGENTS.md“出厂预置”第 1 条）。外壳用官方插件 `tauri-plugin-global-shortcut` 在启动和设置改动时整组重新注册，
   注册失败不弹窗，记下来由新命令 `hotkey_status` 给设置页提示冲突。`Ctrl+Alt+P`、`Ctrl+Alt+R` 仍在核心。
   `hotkey.focus` 随专注计时（FR-RST-10，P2）再加。

## 影响
- 产品书 10 第 5.1 节补四个读取命令与 `hotkey_status`；第 5.2 节补 `mood:typo`、`typing:pulse`，`comfort:new` 加 `trigger`；
  第 6.2 节的 `hotkey.<chat|widget|dashboard|focus>` 落为前三个，写明格式与默认值。
- 07 FR-DSH-03 补一句“主导天气不要求 40%”，与 05 FR-REV-01 晚间小结的口径区分；FR-DSH-04 写明一句话总结的变量写法。
- 15 第 2 节 `weekly_line.toml` 状态从“待接入”改为已加载，可被用户目录覆盖。
- 没有新迁移；导出（FR-DAT-03）多了三个设置键，其余不变。

## 验证
`core/src/domain/dashboard.rs`、`pulse.rs`、`hotkey.rs` 与 `infra/store/dashboard.rs` 的单元测试覆盖主导天气（不足 10 窗、并列、unknown）、
时间线（合并、断开、unknown 当空白）、按本地日期归天与日记标记、热力图与最累钟点、一句话规则与变量缺值、脉冲的来源与上限、
快捷键格式；外壳测试覆盖 `day_stats` 只读当天、反馈解析、快捷键默认值都能映射到插件的键码。
`bindings.ts` 由 CI 的 export-bindings 核对。
