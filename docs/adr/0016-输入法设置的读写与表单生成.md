# 0016 输入法设置的读写与表单生成
- 状态：提议
- 日期：2026-10-05；决策人：D（提议，`bindings.ts` 契约负责人）；待 A（输入法核心）、C（Hub 后端）评审

## 背景
产品书 07 FR-SET-02 要求设置中心的“输入法”分类**按 wind-rpc `config.schema` 自动生成表单**，10 第 5.1 节给了三个透传命令
`ime_schema` / `ime_config_get` / `ime_config_set`，17 第 2.1 节把 wind-rpc 客户端放在 `infra/imeconf.rs`。实现前核对了现状：

- **心晴不带清风的设置程序**：身份改造后，托盘“设置”打开的是 `xinqing_hub.exe`（`docs/xinqing/identity.md`），
  `wind_setting.exe` 不在心晴的安装包里。输入法的全部设置只能在 Hub 里改。
- **`config.schema` 只给键名、类型和枚举取值**：`{"fields": [{"key", "type", "options"?}]}`，类型是
  `bool / int / float / string / enum / string[] / map / array`；没有中文名称、说明、数值范围，也没有分组。清风自己的设置程序
  另有一份逐项手写的清单（`wind-setting` 仓库的 `settings_manifest.toml`）补这些信息，心晴没有它。
  直接按 schema 生成，界面上只能显示 `ui.candidate.layout` 这样的键名。
- wind-rpc 的控制通道是 4 字节大端长度前缀 + JSON 的请求-响应，心晴版管道名 `\\.\pipe\xinqing_rpc_ctrl{后缀}`
  （开发版后缀 `_dev`），每次连接处理一条请求（`wind-rpc/src/client.rs`）。

## 决策
1. **三个命令按 10 第 5.1 节的名字实现，形状如下**（全部 async，阻塞的管道读写放进 `spawn_blocking`）：
   - `ime_schema() -> ImeField[]`：`{key, kind, options}`。`kind` 是 `bool / int / float / string / enum / string_list / map / array`，
     认不出的类型归为 `other`（07 的“其他：只读 JSON”）。
   - 配置值是任意 JSON，在 TypeScript 里是 `unknown`：specta 把 `serde_json::Value` 当递归类型内联导出会栈溢出，
     所以值字段用 `#[specta(type = Unknown)]` 标注，由前端按 `ime_schema` 的类型判断。
   - `ime_config_get() -> {values}`：`values` 是整份合并后的配置（`config.get`），界面按键名的点分路径取值。一次取全，不逐键 `getItem`。
   - `ime_config_set(items: {key, value}[]) -> {needs_restart, applied, skipped: {key, reason}[]}`：透传 `config.setItems`，
     失败项不让整批失败，界面把 `reason` 显示在对应控件旁（17 第 3.4 节）。`needs_restart` 为真时显示 FR-SET-01 的重启横幅。
   - 输入法核心没有运行（连不上管道）时三个命令都返回 `error.ime_unavailable`（“输入法还没启动……”），不重试、不报技术细节。
2. **客户端在 `xinqing_hub/core/src/infra/imeconf.rs`，只用标准库**：Windows 上用 `std::fs::OpenOptions` 打开命名管道，
   其他平台用 Unix 套接字（只为测试和非 Windows 开发）；**不依赖清风的 `wind-ipc` / `wind-rpc` crate**，两个 workspace 保持分开
   （ADR 0007）。帧格式和协议版本号（`PROTOCOL_VERSION = 1`）在本地重写一份，并加一条测试读取
   `wind_input/crates/wind-ipc/src/rpc.rs` 核对版本号，两边不会悄悄走样。环境变量 `XQ_IME_RPC` 可指定管道或套接字路径。
3. **偏离 07 FR-SET-02 的一点：不是“全部自动生成”，而是“常用项手写名称、其余按 schema 生成”**：
   - 前端维护一张**常用项清单**（键名 → 文案键，文案在 `ui_copy.toml` 的 `[ime]` 下），只覆盖 07 点名的“常用”分组（输入方案、
     候选个数、中英切换键、主题）和少量高频项；这些项有中文名称，按 schema 的类型选控件。
   - 其余已登记的键仍**按 schema 自动生成**，名称直接显示键名，放在“高级”折叠区。新增配置项不需要改 Hub 也能出现在“高级”里。
   - 数值类没有范围信息时只给数字输入框，不给滑块（07 要求的滑块需要范围）；写入是否合法由核心的 `config.setItems` 校验。
4. **`config.changed` 事件这一版不订阅**：设置页在打开和保存后重新取一次 `ime_config_get`。订阅事件通道
   （`xinqing_rpc{后缀}_events`）要常驻一个读线程，随后单独做，届时增加 `ime_config:changed` 事件。
5. **快捷键录制框的键名表**（07 要求与清风 `KEY_TABLE` 逐字一致）这一版不做：按键类配置先当字符串显示在“高级”里，
   录制框随后单独提 PR，键名表从核心取，不在 Hub 里抄一份。

## 备选方案与取舍
- **让 Hub 依赖 `wind-rpc` crate 直接调它的 `client::call`**：要把清风 workspace 的 `wind-config`（连同词库、TOML 合并等）拉进心晴
  workspace，和 ADR 0007 的分离相冲突；协议本身只有长度前缀加 JSON，自己写几十行更干净。没有采用。
- **把 `wind-setting` 的 `settings_manifest.toml` 搬进心晴**：那是另一个仓库的数据，几百项都要跟着上游维护，而且要在两个仓库
  之间同步键名（清风 AGENTS.md 记录过键名不一致导致设置静默失效）。只手写常用项，其余靠 schema，维护面最小。没有采用。
- **请 A 给 `config.schema` 加上名称和范围**：要改清风的 wind-rpc，与 10 第 4 节“不为心晴新增 RPC 方法”的规则相冲突；
  也会和上游合并打架。没有采用。

## 影响
07 FR-SET-02 第 1 条（改为“常用项有名称、其余按 schema 生成并放在高级区”，并注明数值无范围时不给滑块）；
10 第 5.1 节“输入法设置”一行（补上三个命令的参数与返回）；17 第 3.4 节（`SchemaForm` 的输入改为 `ime_schema` + 常用项清单）。
接受后同步修改产品书并在 00 第 5 节记录。
