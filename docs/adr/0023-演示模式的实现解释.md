# 0023 演示模式的实现解释
- 状态：提议
- 日期：2026-10-05；决策人：B（B-10 负责人）；待 C（设置键注册表、`DbWriter`）、D（界面、绑定）、E（数据隔离与验收）评审

## 背景
07 FR-DMO-03 要求演示模式“在开发者选项中开启”，开启后：① 时间加速 ×60（替换 Hub 的 `clock`，03 第 4 节）；② 使用独立的演示数据库
（预置一周情绪日历、周报、两条待确认日程），不污染真实数据；③ 演示者视图；标题栏显示“演示模式”。规格没有说：

- 怎么开启：设置键 `dev.demo` 在 10 第 6.2 节列了，但还没登记进设置键注册表（C）；切换数据库又必须重启；
- 加速时钟和 XQP 时间戳的关系：上行 `ts` 是核心的相对毫秒（ADR 0021 背景），按真实速度走；
- 演示库每次是新的还是接着上次用、同意怎么办（新库没有同意就会进入首次引导）；
- 预置哪些表、预置多少。

## 决策
1. **开启方式：启动参数 `--demo`**（发行构建同样有效，演示用的就是安装包）。只在第一个实例启动时生效：Hub 已经在运行时，
   第二个实例把参数转交后退出（17 第 2.2 节），所以要先退出 Hub 再带 `--demo` 启动。C 把 `dev.demo` 登记进注册表后，
   外壳在启动时读真实库的这个键，为真时等同 `--demo`，界面提示“重启后生效”；这一步留给 C，不在本 ADR 里加键。
2. **时钟：`ScaledClock`**（`core/src/infra/clock.rs`）。从启动那一刻（调试构建设了 `XQ_SIM_START_AT` 时从那个时刻）起，
   真实 1 秒 = 演示 60 秒；用单调时钟计流逝，系统改时间不影响。经 `sim::clock()` 交给感知、休息提醒、暖心话、对话、网关；
   B 负责的命令（反馈、自评、作息洞察、重置基线）和启动时的基线重算、“不准”重放也改用它。
   - **打字特征不加速**：窗口里的间隔、速度都按 XQP 的真实毫秒算，否则特征全部失真。窗口所属的本地时刻在每次会话开始时
     按演示时钟定一次（`set_base_local`），之后按真实速度往后推，所以和演示时钟会越差越远；需要深夜场景时用 `XQ_SIM_START_AT`。
   - **休息提醒按演示时钟**：护眼的 20 分钟连续使用 = 真实 20 秒，停顿 ≥2 分钟断开 = 真实停 2 秒。
   - 其他角色的命令（同意、导出、删除对话、暖心话反馈等）和自动清理仍用系统时间，演示中这些记录的时间戳是真实时间，
     各负责人按需改用 `sim::clock()`。
3. **演示库每次重建**：数据目录下的 `xinqing_demo.db`，每次以演示模式启动先删掉旧文件（连同 `-wal` / `-shm`）再新建，
   每场演示看到的“过去一周”都一样；真实库 `xinqing.db` 不打开写连接。
4. **同意沿用真实库**：真实库里已经给过的同意（按当前隐私说明版本）照搬进演示库，免得每场演示都先走首次引导；
   真实库不存在时不新建它，演示库没有同意，照常进入引导。演示中改同意只改演示库。
5. **预置内容**（`domain::demo::seed`，一个事务内完成，数值都是编造的，不含任何文字）：
   - 7 天 × 45 个特征窗口（09:00–23:40 每 20 分钟），特征围绕出厂默认值做可复现的小幅波动，状态段落对应的特征按状态偏移；
     数量越过冷启动（≥200），启动时的重算照常得出个人基线（两个分桶都 ≥30 个样本）；
   - 每个窗口一条状态记录（`source = rule`），大部分流畅，每天穿插一段犹豫 / 低落 / 烦躁 / 疲惫；
   - 每天的 `daily_summary` 计时列（使用时长、提醒次数、完成次数、饮水次数、当晚停止打字时间，其中一晚过了午夜）；
   - 3 条自评天气（不带备注）；两条待确认日程（明天 14:00“小组讨论”、后天截止“交实验报告”）。
   情绪日历用的 `state_dist_json` / `dominant_state`、周信、晚间小结不预置，由各自的汇总生成后再补。
6. **界面**：新增 `demo_status` 命令返回 `{ enabled, speed }`，标题栏的“演示模式”字样、演示者视图（FR-DMO-03 第 3 条）由 D 做。

## 备选方案与取舍
- 立刻加 `dev.demo` 设置键：注册表是 C 的契约，而且切换要重启，单独由 C 加更合适（见第 1 条）。
- 演示库接着上次用：多场演示后数据越来越乱，第二场看到的“周报”和第一场不同，没有采用。
- 打字特征也按演示时钟换算：特征的速度、间隔会放大 60 倍，状态识别全部失真，没有采用。
- 用 `XQ_HUB_DATA_DIR` 指到另一个目录代替演示库：会连密钥、日志一起换掉，演示时还要重新填 API Key，没有采用（该变量仍可用于测试）。
