# 0019 设置值的列表与格式类型
- 状态：提议
- 日期：2026-10-05；决策人：C（提议，设置键注册表的契约负责人）；待 D（`bindings.ts` 契约、设置页）、E（隐私、导出导入）评审；
  B 知会（休息提醒的勿扰可以共用第 6 条的列表）

## 背景
10 第 6.2 节列出了 `care.quiet_hours`、`care.dnd_apps`、`ai.daily_caps`、`safety.school_phone` 等键，但设置值只有布尔、数字、
枚举字符串三种形态（`domain::settings::SettingValue`），这几个键放不下：ADR 0015 第 6 条（安静时段、自定义勿扰应用）和
ADR 0018 第 8 条（学校心理中心电话）都因此推迟。本 ADR 一次把设置契约扩好，并补上暖心话的这两项勿扰。

## 决策
1. **`SettingValue` 新增字符串列表**：Rust `SettingValue::List(Vec<String>)`，前端类型变为
   `boolean | number | null | string | string[]`，落库是 JSON 数组。**列表整份读写**：界面删掉一项，就是用 `settings_set`
   写入删掉后的整份列表，不提供按项增删的命令。出厂值只是默认值，用户清空后存的是 `[]`，读回来也是空的，不会再合并回来
   （与 AGENTS.md“出厂预置的绑定 / 开关，落点必须是用户能清空的载体”一致）。
2. **`Kind` 新增三种取值范围**：`Int { min, max }`（闭区间内的整数，落库仍是 JSON 数字）、`Text(Item)`（一段文字）、
   `List { item, max }`（最多 `max` 项，每项按 `Item` 校验，忽略 ASCII 大小写后不许重复）。`Item` 是已知格式：
   `App`（进程名）、`TimeRange`（时段）、`Phone`（电话）。写入时不合法返回 `settings.out_of_range`，库里已不合法的值读出时回落默认值，
   与原有规则一致。
3. **文字类设置只收已知格式，不收任意文本**。学校心理中心电话会显示在求助卡片里，而 `safety.card` 是豁免禁用词校验的固定文案
   （`banned_words.toml` 的 `exempt_copy_ids`），任意文本会绕过 V4；所以电话只允许数字、空格和 `+-()`，至少 3 个数字，
   不超过 24 字，空串表示没填。以后要加别的文字类设置，先在 `Item` 里加格式。
4. **`ai.daily_caps` 拆成每类一个整数键**：`ai.cap.jev`（默认 3000，0–20000）、`ai.cap.llm`（200，0–2000）、`ai.cap.chat`
   （100，0–1000）、`ai.cap.schedule`（50，0–500）、`ai.cap.rewrite`（100，0–1000），默认值与 FR-AIG-07 和
   `BudgetKind::default_cap` 一致（单测核对），0 表示当天不用这一类。拆开而不做成表，是因为每一项都有自己的范围，设置页按数字输入框
   逐项显示即可，不需要再加“表”这种值。外壳启动时和 `settings_set` 改了 `ai.cap.*` 时把上限交给网关（`set_cap`），立即生效，
   今日已用的次数不清零。周信的“每周 2 次”按周计，不在这里，随 C-10。
5. **安静时段 `care.quiet_hours`**：每项 `"HH:MM-HH:MM"`（24 小时制、两位数），按本地时间判断，包含起点、不含终点，
   起点晚于终点表示跨午夜（`"22:30-07:00"`），起止相同不合法；最多 4 段，默认没有。只约束**主动关怀**（FR-CMF-01 第 5 条），
   负面自评的回应、求助卡片不受影响。06 的休息提醒、日程提醒的勿扰条件里没有安静时段，这里不扩大到它们。
6. **勿扰应用 `care.dnd_apps`**：每项是进程名（如 `Zoom.exe`，不收路径），忽略大小写比较，最多 32 项；默认是 FR-CMF-01 第 5 条的
   `wemeetapp.exe`、`Zoom.exe`、`ms-teams.exe`，用户可以删掉。PowerPoint 放映仍由前台全屏探测覆盖。只在内存里与 XQP `focus`
   事件的进程名比较，不落库别处、不出网。07 FR-SET-05 只有一个“勿扰应用”设置项，所以 06 休息提醒的勿扰应用也建议读这个键
   （判断函数在 `domain::dnd`，B 接时直接用）。
7. **系统专注助手暂不判断**：Windows 没有公开接口读取专注助手（“请勿打扰”）的状态，只有未公开的 WNF 状态；`SHQueryUserNotificationState`
   的 `QUNS_QUIET_TIME` 指的是新用户登录后的一小时，不是专注助手。先不做，FR-CMF-01 第 5 条的这一项留作已知差距。
8. **这次没有加的键**：`chat.retention_days`（随 C-07 的历史设置一起做，值域是 30 / 90 / 365 天与“永久”）；`ai.llm_models`
   （仍按 ADR 0012 随 `secrets_set` 保存）；设置页若要“键注册表 → 表单 schema”的命令，由 D 提出后再加。
9. **只读命令 `settings_schema()`**（D 在评审里提出）：返回全部设置键的 `SettingField[]`，每项 `{key, kind, default}`；
   `kind` 是按 `type` 区分的联合类型（`SettingFieldKind`）：`bool`、`number {min, max}`、`int {min, max}`、`choice {options}`、
   `text {item}`、`list {item, max_items}`，`item` 是格式名（`SettingItem`：`app` / `time_range` / `phone` / `research_id`）。
   与 `ime_schema` 对称，数据就是 `KEYS` 本身（`settings::schema()`），设置页不必在前端另抄一份范围。
   格式名只告诉界面“这是哪种格式”，具体规则（时段写法、电话字符）仍以后端校验为准，不合法时 `settings_set` 返回 `settings.out_of_range`。

## 备选方案与取舍
- 第 1 条也可以让 `SettingValue` 收任意 JSON（`serde_json::Value`）：前端类型变成 `any`，校验散落到各处，没有采用。
- 第 4 条也可以给 `SettingValue` 加“表”（`Record<string, number>`）：多一种值只为这一个键，设置页还得为它单做控件，没有采用。
- 第 6 条也可以保留出厂列表、用户列表只做追加：用户就没法让某个出厂应用不再勿扰，正是 AGENTS.md 记下的那类关不掉的问题，没有采用。

## 影响
10 第 6.2 节（设置值的四种形态；`ai.daily_caps` 改为 `ai.cap.*`；`care.quiet_hours`、`care.dnd_apps`、`safety.school_phone` 的格式、
默认值与取值范围）；05 FR-CMF-01 第 5 条（安静时段的格式、专注助手暂不判断）；08 FR-AIG-07（上限对应的设置键）；
07 FR-SET-05、FR-SET-08（设置页控件）；10 第 5.1 节（新增命令 `settings_schema`）。`settings` 表结构不变，**不加迁移**；导出、导入照常只处理 `KEYS` 里的键，列表值原样带走。
接受后同步修改产品书，并在 00 第 5 节记录。

## 评审
- D（2026-10-05，`bindings.ts` 契约、设置页）：**同意**。`SettingValue` 加上 `string[]` 后前端照常（设置缓存原样存取，列表整份写回）。
  第 8 条提到的“键注册表 → 表单 schema”，D 在这里提出：设置页做“关怀”“AI 服务”等分类时，要知道 `Int` 的上下限、`List` 的最多几项与每项格式，
  才能给数字框和列表控件设范围、写提示，不想在前端再抄一份范围（`ai.cap.*` 五个键各有各的范围）。建议加只读命令 `settings_schema()`，
  返回每个键的 `{key, kind}`（`kind` 带 `min` / `max` / `max_items` / `item`），与 `ime_schema` 对称；D 写设置页之前另起契约 PR 商定，不阻塞本 ADR。
- C（2026-10-05）：按 D 的提法加了 `settings_schema()`，见第 9 条。类型名用 `SettingField` / `SettingFieldKind` / `SettingItem`，
  避免 `Item`、`FieldKind` 这种太泛的名字进前端全局类型。`min` / `max` 在生成的类型里是 `number | null`（specta 对 `f64` 的通常写法），实际总有值。
