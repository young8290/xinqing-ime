# 0011 自评天气（FR-STA-10）的几处实现解释
- 状态：提议
- 日期：2026-10-04；决策人：B（提议）、E（同意，2026-10-04），待 D 评审

## 背景
实现 FR-STA-10（`xinqing_hub/core/src/domain/self_report.rs`、`sense.rs`）时，规格没有说清以下几点。

## 决策
1. **“说不上来”不覆盖显示**，并且结束之前的覆盖、回到自动判断。它没有对应的天气；用户说“说不上来”时继续显示上一次自评的天气也不合适。照常写库，`self_report:changed` 的 `until_ts` 等于自评时刻。
2. **校准的计法**（第 3 条“差异连续 3 次以上时按 FR-STA-06 第 8 条调整”）：
   - “差异”指自评对应的状态与同一时刻自动判断的显示状态不同；“说不上来”不算差异，也不打断连续；没有自动判断（还没有窗口）时算打断；
   - 连续差异每满 3 次（第 3、6、9…次），把**这一次被否定的自动状态**的阈值上调一档（+0.05，上限 0.95，持续 7 天），与“不准”3 次的效果相同；
   - 被否定的自动状态是 `fluent` 时不调整：流畅没有可上调的阈值（FR-STA-06 第 7 条的 0.6 管的是回到流畅）。
3. **自评期间的状态解释**：`state_explain()` 返回 `source = self`、没有信号和可能性的解释，界面据此显示“你说的”；覆盖结束后恢复为自动判断的解释。
4. **总线事件** `HubEvent::SelfReport` 的 `weather` 用自评选项 `SelfWeather`（含 `unsure`），不用 10 第 5.3 节写的 `Weather`：`Weather` 里没有“说不上来”，却有不会被自评选中的 `wind`。
5. **自评覆盖不跨重启**：只存在感知任务内存里，Hub 重启后回到自动判断。自评记录本身在库里，界面可以用 `self_report_list` 自己判断最近一次是否还在 60 分钟内。

## 备选方案与取舍
- 第 2 条也可以理解为“连续 3 次差异后每次都上调”：会让阈值很快顶到上限，没有采用。
- 第 5 条可以在启动时读最近一次自评恢复覆盖，暂不需要，留作以后的改进。
