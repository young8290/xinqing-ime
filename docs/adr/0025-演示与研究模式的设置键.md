# 0025 演示与研究模式的设置键
- 编号：原为 0024，main 上 0024 已被日程待办校验口径（#57）占用，改为 0025
- 状态：提议
- 日期：2026-10-05；决策人：B（DMO 负责人，提议）；待 C（设置键注册表的契约负责人）、E（研究数据处理）评审

## 背景
07 FR-DMO-03 要求演示模式“在开发者选项中开启”，FR-DMO-04 要求研究模式“需在设置中输入研究编号后开启”。10 第 6.2 节列了
`dev.demo`，没有列研究模式的键；设置键注册表（`core/src/domain/settings.rs`）两者都还没有。ADR 0023 第 1 条约定
`dev.demo` 由注册表负责人登记；研究模式（B-10 剩余部分）也要先有键才能做。注册表是 C 的契约，所以单独提这个 PR。

## 决策
1. **`dev.demo`**：`Bool`，默认 `false`。为真时外壳**下次启动**进入演示模式（等同 `--demo`，ADR 0023），
   界面切换后提示“重启后生效”。读取在 B 的后续 PR 里做（外壳启动时读真实库的这个键）。
2. **`research.id`**：`Text(Item::ResearchId)`，默认空串。新格式 `Item::ResearchId`：ASCII 字母、数字、`-`、`_`，
   不超过 16 字，空串表示没填。只收匿名编号（12 第 4 节“匿名编号”），不收姓名、邮箱、空格和中文，
   这样它出现在导出文件和界面上都不会带出个人信息。
3. **`research.enabled`**：`Bool`，默认 `false`。`research.id` 为空时这个开关不起作用（后端按“未开启”处理，
   界面应先让用户填编号再允许打开），不在注册表层面做跨键校验：注册表只校验单个键的取值。
4. 三个键都是普通设置：随导出导入（FR-DAT-03/07），不进 `INTERNAL_KEYS`。

## 备选方案与取舍
- 研究模式只用一个键（填了编号就算开启）：关掉时还要清空编号，研究结束后想看自己用过的编号也看不到，没有采用。
- `research.id` 用任意文本：可能被填成真实姓名，并且绕得过禁用词校验（ADR 0019 第 3 条），没有采用。
- `dev.demo` 立即生效：演示模式要换数据库和时钟，运行中切换牵涉所有服务，没有采用（ADR 0023）。

## 影响
- 10 第 6.2 节键清单补 `research.id`、`research.enabled`；07 FR-SET 开发者选项补“演示模式（重启后生效）”、研究模式的编号与开关。
- 设置界面（D）：开发者选项分类里显示这三个键。
- 接受后同步修改产品书，并在 00 第 5 节记录。
