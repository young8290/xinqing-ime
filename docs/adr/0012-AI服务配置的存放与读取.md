# 0012 AI 服务配置的存放与读取
- 状态：提议
- 日期：2026-10-04；决策人：C（提议）；E（隐私）修改后同意、D（界面）同意，见“评审”

## 背景
C-03 把 AI 网关接进 Hub 外壳时（`xinqing_hub/src-tauri/src/gateway.rs`、`secrets.rs`、`commands/ai.rs`），产品书只规定了
“DPAPI 加密保存为 `hub\secrets.bin`、内存用后清零、界面只显示末 4 位”（08 FR-AIG-06、09 D-19）和三个命令
`secrets_set` / `ai_test_connection` / `ai_usage_today`（10 第 5.1 节），没有规定：文件里存什么格式、设置页怎么拿到
“当前填了什么”、开发时和非 Windows 平台怎么办、换配置后预算怎么算。

## 决策
1. **`secrets.bin` 存整份 AI 配置**：结构与仓库里的 `secrets.example.toml` 相同（`[jev]` 地址、密钥、模型，`[llm]` 地址、密钥、
   模型优先级列表），序列化成 TOML 后整份用 DPAPI（当前用户范围、`CRYPTPROTECT_UI_FORBIDDEN`）加密。地址和密钥是同一张
   D-19 表里的数据，放在一个文件里，“删除全部数据（含密钥）”删这一个文件即可。写入先写临时文件再改名。
2. **新增只读命令 `ai_config_get`**：返回 `{source, jev: {base_url, key_tail, model}, llm: {base_url, key_tail, models}}`，
   设置页（FR-SET-08）和引导页（FR-ONB-05）据此显示当前配置。密钥只进不出：任何命令都只返回末 4 位。
3. **`secrets_set(config)` 里没填的密钥沿用旧值**：`api_key` 为 `null` 或空字符串表示不改密钥，界面因此不需要拿到明文
   也能只改地址或模型；某一侧整个为 `null` 表示清除这一侧；两侧都清空时删除 `secrets.bin`。保存成功后立即换用新网关，返回
   与 `ai_config_get` 相同的结构。地址必须以 `http://` 或 `https://` 开头，否则返回 `error.ai_config_invalid`。
4. **配置来源的优先级**：dev 构建的明文 `secrets.toml`（仓库根目录，或环境变量 `XQ_SECRETS_FILE` 指定，已被 `.gitignore`
   忽略，14 第 4 节）→ `secrets.bin` → dev 构建连本机 mock-ai（14 第 3.3 节）→ 都没有则离线。release 构建只认 `secrets.bin`。
   `ai_config_get.source` 告诉界面当前用的是哪一个（`saved` / `dev_file` / `dev_mock` / `none`）。
5. **非 Windows 平台不保存密钥**：没有 DPAPI，`secrets_set` 返回 `error.ai_secrets_unsupported`，不写任何明文文件。
   Hub 只在 Windows 发布（03 第 7 节），其他平台只用于开发，用第 4 条的 `secrets.toml` 或 mock-ai。
6. **换配置不清零今日预算**：新网关接过旧网关的今日用量和上限（`HttpGateway::inherit_budget`），反复保存配置不能绕过
   FR-AIG-07 的每日上限。熔断与延迟统计随旧网关丢弃（换了地址或模型，旧统计没有意义）。
7. **领域服务拿 `Arc<Ai>`**：外壳托管的 `Ai` 本身实现 `AiGateway`，每次调用转给当前网关，换配置后领域服务不用重新取。
8. **“测试连接”只测大模型**：按 FR-AIG-04 第 4 条逐个模型发最小请求；Jev 没有不消耗额度的探测接口，它的可用性看
   `gateway:health` 和出网日志。

## 备选方案与取舍
- 地址放 `settings` 表、只有密钥进 `secrets.bin`：设置项会随“导入”跨电脑带走地址，而密钥带不走（09 第 6 节），两边对不上；
  且 09 D-19 把地址与密钥列为同一类数据。没有采用。
- 不加 `ai_config_get`，界面自己记住填过的地址：重装或换窗口后界面不知道当前配置，dev 构建也无法提示正连着 mock-ai。没有采用。
- 非 Windows 平台用明文文件保存：与 FR-AIG-06 冲突，没有采用。

## 评审
- E（2026-10-04，隐私与安全）：**修改后同意**。第 1、2、4、5、6、7、8 条同意：整份配置进 DPAPI、密钥只进不出（只回末 4 位）、
  release 构建只认 `secrets.bin`（代码里按 `cfg!(debug_assertions)` 区分，已核对）、非 Windows 不落明文，都符合 FR-AIG-06 与 09 D-19。
  有两处要改，**改完再接受**：
  1. **第 3 条与 09 SEC-02 冲突**：SEC-02 要求“所有外部请求使用 HTTPS”，现在 `check_url`（`gateway/src/secrets.rs`）对任何主机都放行 `http://`，
     release 构建里用户填一个 `http://` 的中转地址，密钥和特征就会明文出网。建议：release 构建只接受 `https://`；`http://` 只放行回环地址
     （`127.0.0.1`、`localhost`、`[::1]`，给 mock-ai 和本机服务用）；dev 构建不限制。ADR 第 3 条的“必须以 `http://` 或 `https://` 开头”相应改写。
  2. **配置解析失败时日志可能带出密钥**：`AiSecrets::from_toml` 把 `toml` 的错误原样放进 `SecretsError::Parse`，外壳 `choose()` 再 `eprintln!` 出来。
     `toml` 的错误信息会引用出错的那一行原文（本地验证过：`TOML parse error at line 4 … | 4 | models = "oops"`），出错的若是 `api_key` 那一行，密钥就进了日志，
     违反 NFR-SEC-02 / NFR-LOG-01。`secrets.bin` 解密后的内容和 dev 的 `secrets.toml` 都走这条路。建议 `Parse` 只保留行号和错误类别
     （例如用 `e.span()` 算行号、`e.message()` 取类别），不带原文；并加一个测试：故意写坏 `api_key` 一行，断言错误文本里没有那段密钥。
  两处都在 C 的代码里，由 C 改；改完请在这里补一句，E 再确认。
- D（2026-10-05，界面）：**同意**。`ai_config_get` 的结构够设置页（FR-SET-08）和引导页（FR-ONB-05）用：`key_tail` 由后端打好码
  （`••••a1b2`）界面原样显示，“空密钥沿用旧值”正好对应密钥框留空、占位提示“留空表示不改”，`llm.models` 的顺序就是可拖动排序的
  优先级。与 E 的意见相关的一处要**一起改**，另有三条不阻塞的建议：
  1. **E 意见第 1 条落地时，`error.ai_config_invalid` 的文案要同一个 PR 改**：现在是“地址要以 http:// 或 https:// 开头……”，
     release 只收 `https://` 后会误导用户。建议改为“地址要以 https:// 开头（本机测试可以用 http://），模型名也不能空着，改一下再保存吧。”
     （`ui_copy.toml`，改后跑 `pnpm gen:i18n` 和禁用词校验。）
  2. 第 8 条“测试连接只测大模型”：界面在结果列表里给 Jev 单独一行，取 `gateway:health` 的 `jev`，注明“没有测试接口，看最近一次调用”，
     不需要新命令。
  3. 新打开的设置窗口拿不到当前两侧的健康状态（`gateway:health` 只在变化时推送，快照里只有合并后的 `offline`）。建议在
     `ai_config_get` 的返回里加 `health: {jev, llm}`，或给一个只读命令；在那之前界面先显示“未知”。
  4. `source` 为 `dev_file` / `dev_mock` 时界面显示一条只在开发版出现的提示（文案由 D 加进 `ui_copy.toml`），`none` 时显示“离线模式”。
