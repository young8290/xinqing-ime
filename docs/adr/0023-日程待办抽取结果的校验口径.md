# 0023 日程待办抽取结果的校验口径
- 状态：提议
- 日期：2026-10-05；决策人：C（日程与待办）；待 E（08 输出校验、评测集）评审

## 背景
`domain::schedule::validate_schedule_json` / `validate_todo_json` 校验 P-SCHEDULE / P-TODO 的输出（xinqing-ime#52、#55）。
做的过程中发现产品书有三处说法对不上或没说清：

1. **标题超长**：06 FR-SCH-03 第 3 条写“`title` 限 12 个字，超出则截断”；08 第 5 节 V3 只列“日程标题 ≤ 12 字；待办标题 ≤ 16 字”，
   按该节“任何一步失败即视为 `InvalidOutput`”就是重新生成一次、再失败转本地抽取。
2. **V4 禁用词、V7 语言**：08 第 5 节写“全部”输出都要过。但日程 / 待办的标题和地点取自用户自己的句子：禁用词表里有“吃药”“治疗”
   “康复”，“按时吃药”“去医院复诊”这类正常日程会被拦下；“交DDL”“Zoom 面试”这类标题中文占比不到 60%。
3. **FR-SCH-04 校验第 1 条**（“模型日期与代码日期不一致 → 采用代码结果，标记 `adjusted`”）需要代码先从原句算出日期，
   此前没有实现；E-EXTRACT 数据集的标注里还有 09 D-12 没列出的 `need_time` 标记。

## 决策
1. **标题超长截断**，日程 12 字、待办 16 字，按 06 FR-SCH-03 第 3 条。截断后满足 08 V3 的上限，不为此多调一次大模型；
   标题为空仍然判失败。
2. **V4 只拦模型带进来的词**：标题和地点里出现的禁用词（含正则），如果原句里也有，就是用户自己的话，照常保留；原句里没有的
   才算命中，判 `Banned` 失败（`BannedWords::find_new`）。**V7 不用于**标题和地点：它们是从原句摘出的短语，模型输出英文或乱码的
   情况 V1、V2 已经挡住。原句只在内存里传给校验函数，不落库（FR-SCH-12 的原句约定不变）。
3. **原句能算出的日期和时刻一律以代码为准**（`domain::when::parse`，按 FR-SCH-04 的星期规则、时刻规则和补充规则 1～6）：
   - 原句有日期：用代码的日期；有钟点：用代码的时刻和区间结束时刻；
   - 原句说了日子或时段（“晚上”“明早”）却没有钟点：时刻为空、全天，模型补的钟点不算数（时刻规则、补充规则 2、6）；
   - 原句有钟点没说日子：日期按校验第 4 条取今天或明天，模型给的日期不算数；
   - 原句里什么都算不出（例如“国庆节”这类产品书没列的说法）：沿用模型的结果；
   - 原句有截止类说法（补充规则 4、5）而模型没标 `is_deadline` 时，按截止处理；
   - 模型给了值而最后用的不是它，标 `adjusted`；模型留空、由代码补上的不标。
4. **标记**：`adjusted`、`maybe_past`、`confirm_date`（09 D-12），加上 `need_time`（非截止的全天日程，卡片提示补充时刻，名称取自 E-EXTRACT）。
   E-EXTRACT 数据集说明里的 `check_date` 改为 `confirm_date`；评测脚本比对标记时不比 `adjusted`（它说明模型错过，不是卡片该带的提示）。
5. 待办的截止日期同样以代码从原句算出的为准（FR-SCH-12“`due_date` 按 FR-SCH-04 的规则由代码校验”）。

## 验证
`domain::schedule` 的单测把 E-EXTRACT 的 60 条逐条跑一遍：模型输出里日期、时刻全部给错（`2026-01-01 03:33`），代码校验后的
日期、时刻、结束时刻、截止、全天和标记都与标注一致。

## 影响
08 第 5 节 V3 补“日程 / 待办标题超出截断”，V4 补“从用户原句抽取的字段只拦原句没有的词”，V7 注明不用于日程 / 待办标题；
09 D-12 的 `flags` 取值补 `need_time`。
