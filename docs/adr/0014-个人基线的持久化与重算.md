# 0014 个人基线的持久化与重算
- 状态：提议
- 日期：2026-10-04；决策人：B（提议）、C（同意，见 xinqing-ime#25 评论），待 E 评审

## 背景
实现 FR-STA-03 第 3–5 条（`xinqing_hub/core/src/domain/features/{baseline,persist}.rs`）时，有几处规格没写清，或现有设计还没有对应的部件。

## 决策
1. **重算的数据来源是 `window_features`**，不在内存里另存 7 天的原始值（17 第 2.3 节原写法）。窗口特征本来就落库（D-06，保留 30 天），重算直接读最近 7 天，Hub 重启也不丢样本；`baseline` 表只存统计值（D-09）。
2. **重算时机**：Hub 启动时一次（补上关机期间错过的 04:00，也让冷启动进度跨重启接续），之后每天 04:00 一次。C 的 `scheduler` 还没有，04:00 先由感知任务按 `Clock` 判断（`Sense::maybe_recompute_baseline`）；`scheduler` 就绪后可以改由它触发，接口是 `SensePort::recompute_baseline`。
3. **“有效窗口数”**（冷启动阈值 200）取最近 7 天、且在上次重置之后的窗口数，与重算用的样本同一口径；两次重算之间每个新窗口 +1。看板历史状态点的解释（`Db::explain_mood_state`）也按这个口径判断冷启动。
4. **分桶的最少样本数**：某时段桶里一个特征少于 30 个样本时，这一格不写个人值，继续用人群默认值。例如很少在夜里打字时，几个夜间窗口算出的中位数不可靠。
5. **重置基线**：新增命令 `baseline_reset`（10 第 5.1 节没有列，对应 07 FR-SET-04 的“重置基线”按钮）。清空 `baseline` 表，并记下重置时间，之后只用重置以后的窗口，重新进入冷启动。重置时间借用 `settings` 表的内部键 `baseline.reset_ts` 存放：它不是用户设置，不进设置键注册表 `KEYS`，`settings_get` / `settings_set` 命令也读写不到它；它登记在 `settings::INTERNAL_KEYS`，导出 / 导入设置时只处理 `KEYS`，不带这个键（换一台电脑导入时，不该用另一台电脑的重置时间过滤本机的窗口）。
6. 值为 `null` 的特征（如未启用 FR-SEN-08 时的 `dwell_med`）不计入样本，与 FR-STA-02 “不得用 0 代替”一致。

## 备选方案与取舍
- 第 5 条也可以新增迁移，在 `baseline` 表加一行元数据或单独一张表：要改 C 的迁移契约，只为存一个时间戳不划算，没有采用。
- 第 3 条也可以按“全部历史窗口数”判断冷启动：重置基线后就回不到冷启动，没有采用。

## 评审
- C（`settings` 表与设置键注册表的契约负责人）：同意第 5 条借用 `settings` 表，建议把内部键登记到 `INTERNAL_KEYS`、导出导入只处理 `KEYS`（已在 #25 里加上）；同意第 2 条先由感知任务按 `Clock` 判断，C-05 做 `scheduler` 时经 `SensePort::recompute_baseline` 接过去，接口不变。ADR 编号按 C 的意见由 0012 改为 0014（0012 已被 AI 服务配置占用）。

## 影响
