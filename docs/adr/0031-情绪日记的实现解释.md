# 0031 情绪日记的实现解释
- 状态：提议
- 日期：2026-10-06；决策人：C（提议，C-10 第三部分）；待 E（隐私、危机安全、空白模板与标题文案）、D（日记界面、对话窗口的“写成情绪日记”）评审

## 背景
05 FR-DIA-01～03 规定了情绪日记：从对话快捷指令“写成情绪日记”或看板“写今天的日记”进入，用 P-DIARY 起草 100–200 字第一人称草稿，
用户可改；按 `ai_draft` / `ai_edited` / `manual` 标识；每天可以多篇；可查看、编辑、删除、导出。FR-SAF-01/02 要求保存日记时同样做危机
识别（本地词表；同意 ② 时另发 Jev），命中时打开对话窗口显示求助卡片。`diary` 表（09 D-13）、P-DIARY、导出都已经有了。

## 决策
1. **代码分三层**：纯函数 `core/src/domain/diary.rs`（对话要点、提示词、草稿校验、来源判断、文案），服务 `core/src/diary.rs`
   （`DiaryService`，与外壳之间只走 `DiaryPort`），外壳 `src-tauri/src/diary.rs` 与 `commands/diary.rs`。
2. **草稿的输入**：
   - 今日状态摘要：与对话共用 `chat::today_summary`（只有统计），**只在同意 ④ 时带**；
   - 对话要点：从对话窗口进来时，取那段对话里**用户自己说的**最近 10 条，每条截到 60 字，合计 ≤ 500 字，用“；”连起来；晴晴的回复不放
     （草稿要像用户自己写的）。产品书没规定“要点”怎么取，这里不另调一次大模型做摘要；
   - 两样都没有时不调用大模型，直接给空白模板（P-DIARY 要求“只写信息中出现过的内容”）。
3. **危机时不起草**：那段对话处于安全模式，或对话要点命中本地词表时，一个字都不出网，直接给空白模板（P-DIARY 不是安全提示词）。
4. **草稿校验**：去掉空白后 30～300 字（V3 上限 300；下限是防止模型没按要求写）、V4 通用禁用词（日记不放行 `chat_allow`，
   FR-DIA-01“不得出现诊断性措辞”）、V7 中文占比。**不重试**：没通过、超时、离线都直接给空白模板（FR-DIA-01 失败处理）。
   空白模板是 `ui_copy.toml` 的 `diary.blank`（“今天发生了…… / 我的感受…… / 明天想……”）。
5. **保存与来源**（FR-DIA-02）：`diary_generate` 返回 `draft_id`，草稿原文只在内存里（最多 20 份、24 小时）。保存时：
   - 新写的：带 `draft_id` 且内容与草稿相同（不计首尾空白）→ `ai_draft`；改过 → `ai_edited`；不带 → `manual`；
     带了但 Hub 已不记得那份草稿（重启过）→ 按 `ai_edited` 标，宁可多标 AI（C-LAW-05）；
   - 改已有的：`ai_draft` 改了内容变成 `ai_edited`，其余不变；
   - 一篇最多 5000 字（产品书没规定，防误粘贴大段文字）；日期记在保存当天；用户确认类数据，同步写（ADR 0020）。
6. **保存时的危机识别**（FR-SAF-01/02）：本地词表先于一切；**同意 ② 时**另在后台发 Q-CRISIS（不阻塞保存），产品书只说手写日记要同意 ②，
   这里对三种来源一视同仁。任一命中：**新开一段安全模式的对话**（标题 `diary.safety_session`“关于今天的日记”，不含日记内容），
   推 `safety:triggered` 并打开对话窗口，对话窗口照常显示求助卡片、之后用 P-CHAT-SAFE；写 `safety_log`（只有时间和通道）。日记照常保存。
7. **命令**（10 第 5.1 节只列了名字）：`diary_generate(session_id?) → {draft_id?, text, ai_generated}`、
   `diary_save(id?, draft_id?, content) → {id, source, safety}`、`diary_list() → 全部，新的在前`、`diary_delete(id)`。
8. **mock-ai 认 P-DIARY**（回一篇能过校验的草稿），`gateway/tests/diary_mock_ai.rs` 端到端跑过网关。
9. 顺带：对话的“今日状态摘要”提成 `chat::today_summary(db, now)` 供两处共用；小组件求助入口用的 `safety_open` 命令
   （ADR 0028 第 4 条的界面要它）也在这次加上：开一段安全模式的对话（标题 `safety.session_title`）并打开对话窗口。

## 没有做的
- 界面（编辑框、对话与日记页、看板“写今天的日记”、对话窗口的快捷指令按钮、情绪日历的小本子图标）：D；
- `get_calendar` 的“是否有日记”：随情绪日历（B / D），`diary_list` 已能按日期分组；
- E-DIARY 评测：要真实接口。

## 备选方案与取舍
- 第 2 条也可以先调一次大模型把对话总结成要点：多一次出网、多一份成本，而用户自己的原话更贴近“像用户自己写的”，没有采用。
- 第 6 条也可以只在当前对话里显示卡片：从看板写日记时对话窗口里可能没有任何对话，新开一段最直接，没有采用。
