# 0008 状态识别规格中几处需要解释的地方
- 状态：提议
- 日期：2026-10-04；决策人：待 B 与 E 评审

## 背景
实现 FR-STA-01～08（`xinqing_hub/core/src/domain/`）时，发现以下几处按字面实现会互相矛盾或无法实现。

## 决策
1. **停顿切窗只在不组字时生效**（FR-STA-01 第 2 条）。字面上“停顿 ≥ 2 秒结束窗口”会让 FR-STA-02 的 `pause_cnt`（组字中 > 3 秒的停顿）永远为 0，R2 的停顿条件也永远不成立。现在：组字中的长停顿留在窗口内并计入 `pause_cnt`，同时从 `active_ms` 中扣除；不组字时停顿 ≥ 2 秒照常结束窗口。30 秒上限不受影响。
2. **回到 fluent 只走第 7 条**（FR-STA-06）。第 4、5 条只用于切到非 fluent 状态，否则一个 p ≥ 0.9 的 fluent 窗口就会把刚切换的状态打回去，违反“相邻两次切换间隔 ≥ 2 个窗口”。
3. **降级模式也有滞回**（FR-STA-08）。只用本地规则时，同一规则状态连续 2 个窗口才切换，连续 3 个无提示窗口回到 fluent，与完整模式的节奏一致。
4. **个人阈值上调**（FR-STA-06 第 8 条）作用于第 4、5 条的 0.90 和 0.70 两个阈值，0.90 + 上调量不超过 0.95。
5. **R1b 暂不实现**。判断“非法拼音音节”需要组字内容，而 XQP `comp` 只发编码长度（FR-SEN-04 有意不发内容）。建议由核心在 `comp{op:"update"}` 中新增可选字段 `invalid: bool`（协议允许新增可选字段），Hub 据此实现 R1b。
6. **同一窗口同时有 core 和 tsf 按键时**（启用 FR-SEN-08 后），按键类特征只用 tsf 来源，避免重复计数。
7. **R4 的“最近 3 个窗口”包含当前窗口**：上上个、上个、当前三个窗口 kpm 严格下降且 bs_rate 严格上升。

## 备选方案与取舍
第 1 条也可以改成“组字中停顿 ≥ 2 秒切窗，但把停顿记到下一个窗口”，实现复杂且窗口边界难以复现，没有采用。

## 影响
04 FR-STA-01、FR-STA-04、FR-STA-06、FR-STA-08；10 第 2.4 节（若采纳第 5 条）。接受后同步修改产品书并在 00 第 5 节记录。
