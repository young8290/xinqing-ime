# 0015 暖心话的实现解释
- 状态：提议
- 日期：2026-10-04（第 9–12 条随 C-04 第二部分补充）；决策人：C（提议），待 B（总线字段、自评回应）、D（`comfort:new`、`care:reduced` 与小圆点）与 E 评审

## 背景
实现 C-04（`xinqing_hub/core/src/domain/comfort.rs`、`core/src/care.rs`、`src-tauri/src/comfort.rs`）时，
05 FR-CMF-01～06 与 04 FR-STA-10 第 2 条有几处没写清，或现有数据结构表达不了。

## 决策
1. **`comfort_log` 加 `trigger` 列**（迁移 `0002_comfort_trigger.sql`，`auto` / `self_report`）。每日上限和冷却只算主动关怀；
   负面自评后的回应同样写进 `comfort_log`（去重、反馈、看板“今日一句”都要它），但不占名额、不重置冷却。
   FR-STA-10 第 2 条只说“不受限制”，没说算不算数；算的话，用户多说几次“有点低落”，当天的主动关怀就没了。
2. **降级运行时不主动关怀**：触发条件 1 要 Jev 的 `need_comfort`，`MoodEvent::Sample` 新增 `need_comfort`、`valence`
   两个字段（Jev 结果，降级时为 `None`），没有 `need_comfort` 就不触发，与 04 FR-STA-08 第 2 条一致。自评回应不看 Jev。
3. **“持续 ≥ 2 个窗口”按显示状态连续相同的窗口数计**，不看时长；无痕开启时清零重数。状态摘要的 `duration_min`
   是这次显示状态从哪个窗口开始算的分钟数。
4. **时段与模板分组**：`time_of_day` 取 05–11 上午、11–14 中午、14–18 下午、18–23 晚上、23–05 深夜；深夜一律用 `late_night` 组，
   其余按状态选组。某组可用的句子都被“最近 10 条”或用户屏蔽排除时，先放宽“最近 10 条”，仍没有再退到 `cheer` 组。
   “简洁”风格从温柔模板里选不超过 15 字的句子（`comfort.toml` 文件头已写）。
5. **重新生成的时限**：第一次生成已用掉 5 秒以上时不再重试，直接用模板，保证触发到显示 ≤ 10 秒（NFR-PERF-05）。
   网关报错（超时、5xx 等，网关已换过模型）时不重试，直接用模板；只有输出没通过校验才重新生成 1 次。
6. **勿扰**：本 PR 做了前台全屏（含 PowerPoint 放映，复用 D 的 `fullscreen::foreground_fullscreen`）和默认勿扰应用
   （`wemeetapp.exe`、`Zoom.exe`、`ms-teams.exe`，按 XQP `focus` 事件里的进程名，只在内存里比较，不落库、不出网）。
   用户自定义的勿扰应用、安静时段（`care.dnd_apps`、`care.quiet_hours`）和系统专注助手留到下一部分：前两个是列表和时间段，
   现在的设置值类型（布尔 / 数字 / 字符串）放不下，要先扩设置契约。
7. **小组件隐藏时的提示**：推 `comfort:new` 后，小组件不可见就经 XQP 下发 `badge {on: true}`，`windows::open(widget)` 时下发
   `badge {on: false}`。不弹窗、不发系统通知（FR-CMF-04 第 4 条、DS-COPY-08）。
8. **新增设置键 `care.level`**（`more` / `normal` / `less` / `off`，默认 `normal`），对应 FR-CMF-06 的四档；10 第 6.2 节只写了键名。
9. **暖心话反馈用单独的命令 `comfort_feedback(id, verdict)`**，`verdict` 为 `useful` / `unfit` / `mute`，写 `comfort_log.feedback`，
   后点的覆盖先点的。10 第 5.1 节只列了一个通用的 `submit_feedback(target, target_id, verdict)`，但状态反馈的取值是“准 / 不准”、
   写 `feedback` 表（D-17），暖心话反馈的取值是三选一、写 `comfort_log`（D-10），硬塞进同一个命令要让两组取值互相校验，不划算。
10. **🔕 到当天 24:00 为止**，只停主动关怀：负面自评的回应、休息提醒不受影响。到期时间存在 `settings` 表的内部键 `care.muted_until`。
11. **自动降档的计法**：今天、昨天、前天这 3 个自然日里每天都至少有一条反馈，且每天的反馈全是 👎 或 🔕（按那句暖心话的日期归天）。
    每次收到负面反馈时判断；最低降到“少一些”，不会自动关掉；降档后只看降档之后的反馈，避免同一批反馈连降几档（降档时间存内部键
    `care.reduced_ts`）。降档后推送 `settings:changed {key: "care.level"}` 和新事件 `care:reduced {level}`，小组件显示
    `widget.care_reduced`（“我会少打扰你一些”）。
12. **内部键登记在 `settings::INTERNAL_KEYS`**：借用 `settings` 表存放、但不是用户设置的键（本 ADR 的两个；B 的 `baseline.reset_ts`
    合并后也登记进来）。它们不在设置键注册表里，`settings_get` / `settings_set` 读写不到；导出、导入（FR-DAT-03/07）只处理注册表里的键，
    内部键不跨电脑带走。

## 备选方案与取舍
- 第 1 条也可以不加列，在内存里分开计数：Hub 重启后当天的次数就对不上了，没有采用。
- 第 2 条也可以在降级时用本地规则代替 `need_comfort`：规格明确降级时不主动关怀（FR-STA-08 第 2 条），没有采用。
- 第 11 条也可以允许一直降到“关闭”：用户没有明确选择，晴晴就自己不说话了，用户可能以为功能坏了；关闭只能由用户在设置里选，没有采用。
