# 0032 日程与待办识别和提醒的实现解释
- 状态：提议
- 日期：2026-10-06；决策人：C（提议，C-05、C-06 剩余部分）；待 E（隐私、新文案、验收口径）、D（卡片层与日程页接事件和命令）、
  A（`commit.text` 与 `tip`）评审；B 知会（`scheduler` 没有做成通用的定时器）

## 背景
06 FR-SCH-01～14 规定了日程与待办的识别、卡片、去重、提醒、导出、冲突。此前已有 L1 初筛（`ScheduleRecognizer`）、抽取结果校验
（`validate_schedule_json` / `validate_todo_json`，ADR 0024）、代码算日期（`domain/when.rs`）和存储，但没有任何服务把它们串起来，
也没有提醒调度。本 ADR 说明串起来的方式，以及规格没写清的地方。

## 决策
1. **代码分层**：纯函数在 `core/src/domain/schedule.rs`（另加本地抽取 `local_schedule` / `local_todo`、提示词 `ExtractPrompts`、
   气泡文案 `CandidateKind::tip`）、`domain/agenda.rs`（冲突、相似、`.ics`）、`domain/reminder.rs`（提醒时刻与文案）；服务
   `core/src/schedule.rs`（`ScheduleService`，识别）、`core/src/reminder.rs`（`ReminderService`，调度）；外壳 `src-tauri/src/schedule.rs`、
   `commands/schedule.rs`。
2. **拼句子**：核心按上屏发 `commit.text`（只有同意 ③ 或 ⑤ 时才发，Hub 再查一次 ③），一次上屏常常只是一个词。识别服务在内存里把上屏
   文字拼起来：遇到 `。！？；\n!?;` 切出一句；**上屏后停 3 秒**或**切换窗口**时把剩下的当一句（聊天里常不打句号就发出去）；缓冲最多
   240 字。原句只在内存里（`Zeroizing`），处理完即丢，不落库、不写日志（FR-SCH-10）。
3. **L2 与每日上限**：Q-PLAN / Q-TODO ≥ 0.80 才继续；**Jev 不可用时这句不提示**（初筛本来就宽，不确认就弹会很吵）。每日命中上限取
   `schedule_patterns.toml` 的 50 与设置 `ai.cap.schedule` 中较小的；网关把每次 Q-PLAN / Q-TODO 记在“日程识别”的每日额度上
   （`BudgetKind::SchedulePrefilter`，原来没人用），`ai_usage_today` 也列出这一项。
4. **L3**：L2 通过后先经 XQP `tip` 冒“📅 识别到日程”/“✅ 识别到待办”，推 `schedule:detected` / `todo:detected`（卡片显示“识别中…”），
   再调 P-SCHEDULE / P-TODO（网关 12 秒）。没通过校验时**重来一次**（08 第 5 节），网关出错（离线、超时、额度用完）不重试；失败或
   模型说“没有”时按本地规则（FR-SCH-03 第 2 条）：日程标题从事件动词起取 8 个字，没有事件动词取句首，日期时刻由代码算，地点留空，
   标 `local`（卡片标注“请确认信息”）；待办标题取“动作词 + 后 6 个字”，**没有截止日期**（照 FR-SCH-12 原文）。
5. **去重与提示**：哈希 24 小时内重复时不再提示，推 `*:ready` 且内容为 `null`，卡片收起。**修了一个单位错误**：原来去重窗口和“7 天未确认”
   按秒算，而库里时间戳都是毫秒（与 `retention` 不一致），等于只去重 86 秒。同一天 ±1 小时内已有标题相似（二元组 Jaccard ≥ 0.6）的已添加
   日程时标 `maybe_dup`；冲突（FR-SCH-11）在卡片就绪、手动新建和修改时都算，没有结束时间按 60 分钟，全天只和全天比，截止类不参与，
   首尾相接不算。
6. **状态**：识别出来的日程和待办都先存为 `pending`（待办原来直接是 `open`，补上了待确认这一步）；手动新建的直接 `added` / `open`，
   不带 `AI 识别`。“忽略”对待办也只留哈希。日程**不改成 `expired`**：晚间小结按 `added` 统计完成的日程（ADR 0029），“已过期”由界面按
   日期分（FR-SCH-09）。
7. **提醒**（FR-SCH-07、FR-SCH-14）：
   - 有时刻的日程提前 `remind_offsets`（新建时默认取设置 `sch.default_offsets`，10 分钟）；截止类默认截止前 1 天 + 2 小时；全天日程当天
     09:00；有截止日期的待办截止前一天 20:00（只在小组件）和当天 09:00；设置 `todo.daily_digest` 开着时每天 09:00 汇总；
   - **没有照 17 第 2.6 节做最小堆**：每秒从库里算一次 `(上次看到, 现在]` 之间到期的提醒（只读最近的已添加日程与未完成待办，量很小），
     添加、修改、删除后不用另外通知调度；“5 / 10 分钟后再提醒”记在内存里，重启后不保留；
   - 看到哪儿了记在内部键 `sch.reminded_until`（排队写，最多隔一分钟）。启动时上次之后、12 小时内到期的集中推一次 `reminder:missed`
     并弹一条“错过的提醒”；第一次运行不补；
   - 到点推 `reminder:due`，同时弹系统通知（`notify.rs`，按钮“知道了 / 5 分钟后 / 10 分钟后”，点了经 `reminder_action` 交回）；
     系统专注助手开着时由系统收进通知中心（C-PLT-09），这里不另判断。日程提醒的操作不写 `reminder_log`（那张表是休息完成率的口径）。
8. **命令与事件**（10 第 5.1、5.2 节只列了名字）：
   - 命令：`schedule_list(status)`、`schedule_confirm(id)`、`schedule_ignore(id)`、`schedule_create(input) → {id, conflicts}`、
     `schedule_update(id, input) → {id, conflicts}`、`schedule_delete(id)`、`schedule_export_ics(ids) → 文件路径`、`reminder_action(id, action)`
     （`ok` / `snooze_5` / `snooze_10`）、`todo_list(status)`、`todo_confirm` / `todo_ignore` / `todo_create(input) → id` /
     `todo_update(id, input)` / `todo_complete` / `todo_delete`；
   - 事件：`schedule:detected` / `todo:detected {card_id}`、`schedule:ready {card_id, schedule?, conflicts}`、`todo:ready {card_id, todo?}`、
     `reminder:due {id, kind, ref_id, title, body}`（10 写的是 `{id, kind, text}`，拆成标题和正文便于卡片排版）、新增
     `reminder:missed {title, body, items}`。
9. **导出到系统日历**（FR-SCH-08）：RFC 5545，`VTIMEZONE` 固定 +08:00（无夏令时），全天日程用 `VALUE=DATE`，截止类只有开始，每个提前量
   一个 `VALARM`；`DESCRIPTION` 取 `ui_copy.toml` 的 `schedule.ics_description`（“由心晴识别添加”）。写到系统临时目录，Windows 上用默认程序
   打开；只导出已添加的。
10. **设置键**：`sch.default_offsets`（单选，分钟：0 / 5 / 10 / 30 / 60 / 1440，默认 10；10 第 6.2 节的键名是复数，沿用）、
    `todo.daily_digest`（默认关）。**新文案**（`[notify]` 的全天、待办前一天、汇总、“10 分钟后”、地点后缀，`[schedule]` 的 `.ics` 说明）须 E 看。
11. mock-ai 认 P-SCHEDULE / P-TODO（日期时刻留空让 Hub 算），`gateway/tests/schedule_mock_ai.rs` 端到端跑过网关。

## 没有做的
- 卡片层（“识别中…”、字段、添加 / 修改 / 忽略、60 秒收起、冲突与相似提示、提醒卡片、错过的提醒）、看板“日程与待办”页、小组件底栏
  “✅ 3 件待办”：D；
- E-PLAN / E-EXTRACT / E-TODO 评测：要真实接口；
- 演示模式的提醒误差：调度每秒看一次，60 倍速下最多晚演示时间 1 分钟（真实时间 1 秒），验收“误差 ≤ 5 秒”按真实时间算是满足的。

## 备选方案与取舍
- 第 2 条也可以让核心按句发 `commit.text`：要改核心与协议（A），而 Hub 拼句只多几十行，没有采用。
- 第 3 条 Jev 不可用时也可以跳过 L2 直接抽取：初筛的误报会全变成卡片，打扰用户，没有采用。
- 第 7 条也可以照 17 做内存里的最小堆：每次增删改都要通知调度、重启要重建，而直接查库同样准、代码少，没有采用。
