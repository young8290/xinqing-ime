# E-STATE 回放脚本录制剧本（初稿）

> 对应：08 §8 E-STATE（7 个脚本、≥ 200 个标注窗口，记录基线一致率，改动后下降不得超过 5 个百分点）；12 §3 E-STATE 构建规范；07 FR-DMO-01（`xq-sim` 内置脚本）；04 FR-STA-01～08。
> 状态：初稿，待两人评审。脚本名与 FR-DMO-01 完全一致，录制产物为 `eval/datasets/state/<脚本名>.jsonl`（建仓库后的路径）。

---

## 1. 通用要求

### 1.1 录制方式
1. 由组员按本剧本**真实打字**，开启 FR-DMO-02 会话录制（录制时自动删除 `text` 字段，小组件显示红点）；
2. 录制时打的内容一律使用**虚构内容**（可以照抄附录 A 的素材），不得写入真实聊天、真实姓名、账号或任何个人信息；
3. 每个脚本由一名组员（演员）完成，另一名组员在旁边用纸笔或计时器记录**段落日志**：每一段开始的时间点和本段意图（例如“03:20 开始犹豫段”）。段落日志只用于标注参考，不进入回放文件；
4. 统一在同一台电脑、同一键盘、清风输入法默认设置下录制；如果某个特征依赖 FR-SEN-08（`dwell_med`、`delete_committed`）而该功能未启用，标注时记为 `null`，不按 0 处理。

### 1.2 基线与时间
- **基线固定**：回放评测时 z 分数依赖个人基线（FR-STA-03）。为保证结果可复现，演员先正常使用心晴 ≥ 200 个有效窗口，导出基线统计值为 `baseline_<演员代号>.toml`，与 7 个脚本一起保存；回放时 Hub 加载该基线文件，而不是冷启动默认值。（需要在 `xq-sim` / Hub 开发者选项中支持“指定基线文件”，W1 确认。）
- **模拟时刻**：`late_night_tired` 需要 `hour` 落在 [23:30, 05:00)。不要求演员真的熬夜：白天录制后，在 JSONL 头部写入 `start_local_time`，由 `xq-sim` 改写时间戳的日期部分（实现方式待 `xq-sim` 负责人确认；在此之前可以在 23:30 后实际录制）。
- **倍速**：评测回放使用 20×；人工验收演示使用 1× 或 5×。

### 1.3 期望结果的写法
每个脚本另附 `<脚本名>.expected.json`，至少包含：窗口切分数量的期望范围、各规则命中次数的期望范围、期望状态序列（按窗口序号）。状态切换按 FR-STA-06 判断：p ≥ 0.90 立即切换；p ≥ 0.70 需连续 2 个窗口；连续 3 个 `fluent` 窗口回到 `fluent`。下文的“期望状态序列”是**人工标注的目标**，模型实际输出与之比较得到一致率。

## 2. 七个脚本

### 2.1 `fluent` 流畅
| 项 | 内容 |
|---|---|
| 场景 | 和朋友在聊天软件里闲聊周末安排（素材 A1），心情平稳，按平时节奏打字，正常选词、偶尔一两次退格 |
| 目标时长 | 15 分钟（预计 50–70 个窗口） |
| 演员要点 | 不刻意加快或放慢；每句写完回车发送；中间可以自然停顿 2–5 秒（会切分窗口），不要在组字中途停 3 秒以上 |
| 期望规则命中 | R1/R1b：0–3 次（自然手误）；R2：0–2 次；R3、R4、R5：0 次 |
| 期望状态序列 | 全程 `fluent` |
| 用途 | 一致率的“正常”对照；检查是否出现无依据的状态切换（误报） |

### 2.2 `hesitant` 犹豫
| 项 | 内容 |
|---|---|
| 场景 | 想给老师写一段请求延期交作业的话，不知道怎么开口（素材 A2）：写一半停住、整段删掉重写、翻页找词 |
| 目标时长 | 12 分钟（预计 40–55 个窗口） |
| 段落安排 | 0–3 分钟：流畅地写开头寒暄；3–9 分钟：犹豫段，至少做出 6 次“组字中停顿 > 3 秒”、4 次“整段取消组字（Esc）”、3 次“翻页 ≥ 3 页再选词”；9–12 分钟：想好了，顺畅写完并发送 |
| 期望规则命中 | R2：犹豫段内 ≥ 8 个窗口命中（`pause_cnt ≥ 2` / `abandon` / `page_flips ≥ 3`）；R3、R4、R5：0 次 |
| 期望状态序列 | `fluent` → （犹豫段第 2 个 R2 窗口后）`hesitant` → 保持 → （恢复段连续 3 个 `fluent` 窗口后）`fluent`；全程相邻两次切换间隔 ≥ 2 个窗口（TC-STA-06） |
| 用途 | TC-STA-06、TC-STA-09；主动关怀不应在冷却期内重复触发 |

### 2.3 `low_long` 持续低落
| 项 | 内容 |
|---|---|
| 场景 | 一个人在宿舍写一篇不太想写的总结（素材 A3），没什么力气：打字明显比平时慢，句与句之间发呆，很少修改 |
| 目标时长 | 60 分钟（TC-CMF-01 要求持续 60 分钟；预计 120–160 个窗口） |
| 演员要点 | 速度约为自己平时的 50%–60%；停顿放在**上屏之后**（句子之间，2–10 秒），组字中途尽量不停 3 秒以上，避免变成犹豫；退格很少；中途不要离开超过 2 分钟（否则 `session_min` 清零） |
| 期望规则命中 | R1：0–3 次；R2：0–3 次；R3：0 次；R4：可能在 45 分钟后偶发（速度若继续下降），记录实际次数；R5：0 次 |
| 期望状态序列 | 前 1–3 分钟 `fluent` → `low` → 保持至结束 |
| 用途 | TC-CMF-01（满足条件后首次关怀；30 分钟内不再触发）；E-STATE 低落类窗口的主要来源 |
| 评审提示 | FR-STA-06 第 3 条：`low` 没有对应的本地提示，所以只有 Jev 概率 ≥ 0.80 时才会切换。评审时请确认这是否符合预期，若实测基本无法切到 `low`，需要在 04 中补充规则或调整第 3 条 |

### 2.4 `agitated` 烦躁
| 项 | 内容 |
|---|---|
| 场景 | 小组作业临交前队友失联，在群里连发消息催促（素材 A4）：打得又快又急，错了就连按退格整段删 |
| 目标时长 | 10 分钟（预计 35–50 个窗口） |
| 段落安排 | 0–2 分钟：正常速度；2–8 分钟：烦躁段，速度比平时快 30% 以上，每个窗口至少一串 ≥ 5 次的连续退格；8–10 分钟：放慢，恢复正常 |
| 期望规则命中 | R3：烦躁段内 ≥ 6 个窗口命中（`kpm_z > 1.5` 且 `bs_rate_z > 1.5`）；R1：若干次（记录，不设下限）；R2、R4、R5：0 次 |
| 期望状态序列 | `fluent` → `agitated` → （恢复段连续 3 个 `fluent` 窗口后）`fluent` |
| 用途 | 烦躁识别；`typo` 事件节流（1 秒内最多 1 次） |

### 2.5 `late_night_tired` 深夜疲劳
| 项 | 内容 |
|---|---|
| 场景 | 深夜赶实验报告（素材 A5），连续写了将近一小时，越写越慢、错字越来越多 |
| 目标时长 | 55 分钟（R4 需要 `session_min > 45`；预计 110–150 个窗口）；模拟开始时刻 23:35 |
| 段落安排 | 0–20 分钟：正常速度；20–45 分钟：逐渐放慢；45–55 分钟：明显变慢且手误、退格增多（每分钟 2–3 次） |
| 期望规则命中 | R5：从第 11 分钟起每个窗口命中；R4：45 分钟后 ≥ 3 个窗口命中；R1：后段增多；R3：0 次 |
| 期望状态序列 | `fluent` → （45 分钟后）`tired` → 保持至结束 |
| 用途 | 疲劳识别；降级运行（FR-STA-08）时 `tired` 由 R4/R5 触发；深夜关怀模板 |

### 2.6 `schedule` 日程
| 项 | 内容 |
|---|---|
| 场景 | 在班级群和小组群里安排事情：确认组会、提醒截止日期、约饭（素材 A6），中间夹杂普通闲聊 |
| 目标时长 | 10 分钟（预计 30–45 个窗口），包含 10 句日程句、10 句干扰句 |
| 演员要点 | 正常节奏；每句单独发送 |
| 文本处理 | 录制会删除 `text`，而日程识别需要上屏文本：录制后由脚本把附录 A6 的 20 句**虚构句子**按顺序回填到对应的 `commit.text`（同时保证 `chars` 与句子长度一致），并在文件头注明“text 为合成内容” |
| 期望规则命中 | R1–R5：基本为 0（R1 自然手误除外） |
| 期望状态序列 | 全程 `fluent` |
| 期望业务结果 | 以 2026-10-03 为“今天”：10 句日程句中 ≥ 9 句出现日程卡片；10 句干扰句出现卡片 ≤ 1 句 |
| 用途 | 演示与端到端回归（L1→L2→L3 全链路）；也用于检查状态识别不受日程识别干扰 |

### 2.7 `typo_burst` 手误
| 项 | 内容 |
|---|---|
| 场景 | 赶时间回消息，手指不听使唤，频繁打错相邻键又马上改（素材 A7，含拼音与少量英文单词） |
| 目标时长 | 8 分钟（预计 25–40 个窗口） |
| 演员要点 | 按段落日志事先标好的位置，故意按错相邻键（如 a→s、n→m、i→o）后立即退格改正，共约 40 次；另外约 15 次打出非法拼音音节后立刻退格（R1b）；其余时间正常速度，不要成串退格 |
| 期望规则命中 | R1 + R1b：合计 ≥ 45 次 `typo` 事件（考虑 1 秒节流后的实际上限，按段落日志核对）；R3：0–2 次；R2、R4、R5：0 次 |
| 期望状态序列 | 全程 `fluent`（`typo` 只是瞬时动画，不进入时间线）；若出现 `agitated`，标注为“需要评审”的边界窗口 |
| 用途 | R1 精确率/召回率（与 TC-STA-04 的 `typer` 脚本互补，这里是真实打字）；检查手误不会被误判为烦躁 |

## 3. 标注说明

1. **标注单位**：FR-STA-01 切分出的每个有效窗口（少于 5 键被合并的窗口不单独标注）；
2. **标签集**：`fluent`、`hesitant`、`low`、`agitated`、`tired`、`unknown`（信息不足、无法判断）。`typo` 是瞬时事件，不作为窗口标签，单独核对 R1 命中；
3. **标注依据**：回放可视化（打字心电图、特征表）+ 段落日志。标注人**看不到** Jev 的判断结果和模型显示的状态，避免被带偏；
4. **两人独立标注**：由两名**非演员**组员分别标注全部窗口，标注期间不交流；
5. **一致性**：计算两人标注的 Cohen's κ（按全部窗口、6 个标签计算），并分别报告每个脚本的 κ；κ < 0.6 时先修订本标注说明再重标；
6. **定稿**：两人不一致的窗口逐个讨论定稿，仍无法达成一致的标为 `unknown` 并在报告中列出数量；定稿结果写入 `<脚本名>.labels.csv`（列：`window_seq, start_ts, end_ts, annotator_a, annotator_b, final, note`）；
7. **报告**：结果写入 `eval/reports/<日期>-E-STATE.md`，包含 κ、各标签窗口数、模型与定稿标签的一致率（作为基线），以及与上一次评测的对比；
8. **隐私**：标注文件中不得出现任何文字内容（`schedule` 脚本的合成句子除外，且只能来自附录 A6）。

## 附录 A 录制素材（虚构）

- **A1 闲聊**：周末去不去爬山、几点出发、要不要带零食、天气怎么样（自由发挥，内容虚构）。
- **A2 请求延期**：“老师您好，我是某某班的同学，这次的实验报告……”（写给虚构的“王老师”）。
- **A3 总结**：写一篇“本学期社团活动总结”，内容虚构即可。
- **A4 催促**：“@小周 你那部分什么时候能发？”“还有两个小时就截止了”“回一下消息好吗”。
- **A5 实验报告**：抄写或改写教材中任意一段实验步骤说明。
- **A6 日程与干扰句（回填用，共 20 句）**：
  - 日程句：好的，周五下午三点在实验楼开组会；明天上午9点前提交实验报告；下周二晚上七点一起吃饭；10月9日答辩，记得准备PPT；后天早上8点在南门集合；周四之前交读书笔记；这周六下午两点面试；10月12日前提交报名表；明晚八点看电影；下周一上午10点去办公室找老师；
  - 干扰句：昨天的组会开得挺久；三点了还没睡；如果周五有空就好了；你明天有课吗？；他说下周要去面试；上周已经交过了；刚才的电影真好看；这个时间点太难约了；周末一般都在宿舍；以前每周都开组会。
- **A7 手误练习**：任意中文短句 + 少量英文单词（如 deadline、project、meeting），按段落日志预先标注的手误位置打。
