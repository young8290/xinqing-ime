## 2. 固定的“今天”

所有期望值都按下面的假设计算，评测脚本必须把同样的值注入流水线（P-SCHEDULE / P-TODO 的 `{date}` `{weekday}` 和 FR-SCH-04 的代码校验），不能用运行当天的系统时间：

- 今天：**2026-10-03（周六）**，时区 Asia/Shanghai
- 当前时刻：**10:00**（用来判断“时刻已过”，例如“早上8点…”顺延到明天、“周六上午九点”取下周六）
- 一周从周一开始：本周 = 09-28～10-04，下周 = 10-05～10-11，下下周 = 10-12～10-18

## 3. 字段定义

### 3.1 `e_plan.jsonl`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `P001`～`P120`；P001～P060 是正例，P061～P120 是负例 |
| `text` | string | 一句聊天文本（已经是单句，评测时不再切分） |
| `label` | 0/1 | 1 = 用户自己确定要发生的未来日程或截止，应该弹出日程卡片；0 = 不应弹出 |
| `l1_expected` | bool | 按 06 V1.2 的 L1 规则**字面**判断，这句是否会进入**日程**流程（FR-SCH-01 命中且未被排除，并且按第 5 条没有被分到待办流程） |
| `category` | string | 正例：`relative_date` / `absolute_date` / `deadline` / `fuzzy_time` / `with_location`；负例：`past` / `hypothetical` / `question` / `current_moment` / `quote` / `time_no_event` / `other` |
| `note` | string | 标注说明，可为空 |

- 每条只归一个主类别。比如“好的，周五下午三点在实验楼开组会”同时含相对日期和地点，归为 `with_location`。
- 负例里有 30 条 `l1_expected = true`（past 2、hypothetical 5、question 2、current_moment 3、quote 7、time_no_event 8、other 3），用来测 L2（Q-PLAN）是否能挡住；其余 30 条应在 L1 就被挡住。
- 60 条正例全部 `l1_expected = true`（修订前 P053“下午三点去找导师签字”漏检，V1.2 把“签字”加入事件动词后命中）。

### 3.2 `e_extract.jsonl`

| 字段 | 说明 |
|---|---|
| `id` / `text` | 与 `e_plan.jsonl` 的正例一一对应 |
| `expected.title` | 事件名，≤ 12 字；评测时**不要求逐字相同**（见第 4 节） |
| `expected.date` | `YYYY-MM-DD`，按 FR-SCH-04 计算 |
| `expected.time` | `HH:mm`；没有具体时刻且不是截止时为 `null` |
| `expected.end_time` | `HH:mm` 或 `null`（只有“两点到四点”这类才有） |
| `expected.all_day` | 没有具体时刻的非截止日程为 `true` |
| `expected.location` | 句中明确说出的地点，否则 `null`，不推测 |
| `expected.is_deadline` | 含“截止 / DDL / deadline / 之前交 / 前提交”或“X点前…交”时为 `true` |
| `expected.flags` | 卡片应带的标记：`maybe_past`（结果早于当前时刻，“时间可能已过”）、`need_time`（全天、提示补充时刻）、`check_date`（超过 365 天，本集没有用到） |
| `weekday` / `note` | 辅助核对用：期望日期是星期几，以及标注说明 |

适用的规范化规则（FR-SCH-04，含 V1.2 补充规则）：

- 无修饰的 `周X` 取今天之后最近的周 X；今天是周 X 且时刻未过时取今天（P015 取 10-03，P016 时刻已过取 10-10）；
- `这周X / 本周X` 取本自然周，已过则带 `maybe_past`（P009“这周五交报告” → 10-02）；`下周X`、`下下周X` 按自然周；
- `下午 / 晚上 h点`（h ≤ 11）→ h+12；`点半` → :30，`一刻` → :15，`三刻` → :45；
- 只说“晚上”或只说“今晚 / 明早 / 上午 / 下午 / 中午”（补充规则 2）→ `time = null`、`all_day = true`、带 `need_time`；
- 今年已过的月日取明年（补充规则 1，P028 → 2027-01-08）；无修饰的“h点”→ h:00（补充规则 3）；“X点前…交”属于截止类（补充规则 4）；“明天之前 / 周五前”取该日（补充规则 5）；行程目的地不填地点（补充规则 7）；
- 截止类没有时刻 → 23:59；
- 有时刻没有日期 → 今天，时刻已过（≤ 10:00）顺延到明天。

所有日期都用 Python `datetime` 按上述规则计算，并由校验脚本核对：句中写了星期几的，期望日期的星期必须一致。

### 3.3 `e_todo.jsonl`

| 字段 | 说明 |
|---|---|
| `id` | `T001`～`T080`；T001～T040 是正例，T041～T080 是负例 |
| `text` | 一句聊天文本 |
| `label` | 1 = 用户自己之后要做的一件具体的事（Q-TODO 的含义）；0 = 不是 |
| `expected` | 正例为 `{"title": 动词开头 ≤ 16 字, "due_date": "YYYY-MM-DD" 或 null}`；负例为 `null` |
| `category` | 正例：`todo_no_due`（25 条）/ `todo_with_due`（15 条）；负例：`remind_other` / `past_done` / `vague_wish` / `schedule_like` / `third_party` / `memory_recall` / `other` |
| `l1_route` | 按 06 V1.2 FR-SCH-01 / FR-SCH-12 和 `hub_templates/schedule_patterns.toml` 的 L1 规则字面判断这句会进入的流程：`todo`（命中待办初筛且不含时刻类）/ `schedule`（否则命中日程初筛）/ `none` |
| `note` | 标注说明 |

`due_date` 按 FR-SCH-04 计算：“周五前” → 2026-10-09，“这周日前” → 2026-10-04，“下周一之前” → 2026-10-05，“15号前” → 2026-10-15，“今晚” → 2026-10-03。

## 4. 怎么跑评测

评测脚本放在 `eval/` 下（例如 `eval/run_schedule_todo.py`），读 jsonl，逐条调用流水线，把结果写进 `eval/reports/<日期>-<评测集>.md`（12 §3）。

1. **E-PLAN**
   - L1：对每条调用本地初筛，得到 `l1_pass`。L1 召回率 = 正例中 `l1_pass = true` 的比例，门槛 ≥ 98%。同时把 `l1_pass` 和 `l1_expected` 逐条对比，不一致说明 `schedule_patterns.toml` 和 06 的字面规则不一致，要列出来。
   - L1+L2：`pred = l1_pass and Q-PLAN 得分 ≥ 0.80`，与 `label` 比较，计算精确率、召回率和 F1，门槛 F1 ≥ 0.90。
2. **E-EXTRACT**：对 60 个正例都直接调用 P-SCHEDULE + FR-SCH-04 代码校验（不经过 L1/L2，避免前面的漏检影响抽取的得分）。
   - 主指标“日期和时刻准确率” = `date`、`time` 两项**都**与期望相同的条数 / 60，门槛 ≥ 90%；
   - 辅助指标分别报告：`end_time`、`all_day`、`is_deadline`、`location`（完全相同才算对）、`flags` 的准确率；`title` 不逐字比对，由两人抽查“是否表达了同一件事”。
3. **E-TODO**
   - L1：把流水线实际分流结果与 `l1_route` 逐条对比，不一致的列出来；
   - 判定：`pred = (实际分流 == "todo") and Q-TODO 得分 ≥ 0.80`，与 `label` 比较算精确率、召回率和 F1，门槛 ≥ 0.85。按 V1.2 一个句子只进一个流程，所以分到日程的待办句（目前 1 条正例：T040）在本集里算漏检；
   - 对 `label = 1` 的条目再调用 P-TODO：报告 `due_date` 准确率（含 null 也要相同），`title` 人工抽查。
4. 每次改动 Q-PLAN / Q-TODO / P-SCHEDULE / P-TODO 或正则表后都要重跑，报告里写明所用的问题和提示词版本（08 §8）。

## 5. 标注中发现的规范问题与 V1.2 处理情况

初稿按修订前的 06 标注时报告了 6 个问题，第一次重算后又列出 5 个未解决项。06 V1.2 和 `hub_templates/schedule_patterns.toml` 两次修订后，`l1_expected` 和 `l1_route` 已按最新规则重新计算。文本、`label` 和抽取期望值都没有变；`e_extract.jsonl` 只更新了引用规则的 `note`。

当前结果：
- E-PLAN：60 条正例全部 `l1_expected = true`；30 条负例 L1 放行，30 条被挡住。
- E-TODO：39 条正例 `l1_route = todo`，只有 T040 走 `schedule`；负例中 14 条走 `todo`，8 条走 `schedule`，18 条走 `none`。

### 5.1 已解决

1. **带截止日期的待办进不了待办流程**：FR-SCH-01 第 5 条改为“命中待办初筛且不含时刻类 → 待办，日期或截止词作为截止日期”，FR-SCH-12 的 L1 开头也已改成与此一致。15 条 `todo_with_due` 正例中 14 条现在走 `todo`（修订前一条也没有）。含时刻的 T070“记得明天下午两点在实验楼开会”、T071“别忘了后天上午十点答辩”仍走日程，符合预期。
2. **“上周五”被当成未来日期词**：相对日期正则不再匹配前面紧跟“上 / 上个”的星期，排除词加了 `上个?(星期|礼拜)`。P063、P068 现在被 L1 挡住。
3. **数字被误当成日期**：已部分解决，“3号楼”（P116）、“19.9”（P119）现在被挡住。“3.5”和“1.2”仍未解决，见 5.2 第 1 条。
4. **提示词自我命中**：动作词改为在去掉提示词后匹配，“改天一起吃个饭吧”（T058）现在被挡住。
5. **“还”的范围**：“还”后面紧跟 `是|有|在|要|没|记得|好|可以|行|挺|不|会|能|得` 时不算动作词，其余都算。T006“书还了”、T033“还图书馆的书”现在都走 `todo`。
6. **提示词不全**：加了 `得把|要把|得先`，T029“下周一之前得把党课心得交了”现在走 `todo`。
7. **其他人提醒的排除不明确**：现在的写法是 `(提醒|叫|让)` 命中且下一个字不是“我”，本集按这个写法实现。T046、T047 被挡住。
8. **带“记得”、有日期、没有时刻的日程会进待办**：06 已写明这是有意的设计，生成带截止日期的待办卡片。
9. **FR-SCH-04 没写的情况**：已写入 FR-SCH-04 补充规则 1～7，与本集的处理一致。
10. **“/”不在绝对日期正则里**：**这一条是初稿看错了**。修订前的 `[./-]` 本来就包含“/”，P026“10/25”一直能命中日期类。
11. V1.2 还新增了“签字 / 答疑 / 值班 / 体检”事件动词（P053 现在能命中）和“补办 / 要回”动作词（T013、T018 现在走 `todo`）。toml 的截止类比 06 多了 `点前交`，本集也已加上，但不影响任何一条的结果。

### 5.2 仍未解决（请评审时确认）

1. **月.日形式的数字**：“绩点3.5”（P115）和“这个版本是1.2的”（P118）分别符合 3月5日、1月2日的格式，L1 仍放行，只能靠 L2 挡。可以接受（宁可多放过），代价是多一次 Jev 调用。
2. **要靠 L2 挡的负例**：
   - E-PLAN 有 30 条负例 L1 放行：time_no_event 8、quote 7、hypothetical 5、current_moment 3、other 3（含上面两条数字）、past 2、question 2。
   - E-TODO 有 14 条负例走 `todo`：
     - 第三人称：T073“室友需要买个台灯”、T074“他得去补交材料”、T075“组长回头会把文档发群里”、T076“我妈待会要去超市买菜”；
     - “记得”表示回忆：T056、T077、T078；
     - 空泛愿望：T059、T061、T063“等下辈子”、T064“改变”；
     - “爸你记得…”（T048，称呼在“你”前面，不触发第二人称排除）；
     - T079“需要的话可以联系我”、T080“回头看看这一年”。
     L1 没有第三人称排除。如果 L2 挡不住，再考虑排除以“他 / 她 / 室友 / 我妈”等开头的句子。
3. **T040“周四前得联系好实习单位”仍走日程**：“得 + 动词”里只有“得去 / 得把 / 得先”是提示词，“得联系”不是，所以只命中日期类。这条仍按待办正例计入，算 L1 漏检。是否要把“得 + 动作词”也算作提示词，请评审时决定。
